### Scoped query — one symbol, one day

The far more common desk query is "pull one name for one day" — an as-of join scoped to a single symbol-day (**14112** result rows). The intuitive expectation is that `by_date_symbol` wins here by pruning to one file. It does not, and that is the point: at this scale a full scan is cheap, while directory partitioning adds per-file open overhead. `by_date_symbol` creates one small file per symbol-day, so it is the *slowest* — the small-files anti-pattern. Timed from Parquet, median ms.

| Query | single | by_date | by_date_symbol | sorted |
|---|--:|--:|--:|--:|
| scoped as-of (1 symbol × 1 day) | 24 ms | 20 ms | 17 ms | 13 ms |

The scale-dependence is the migration lesson — see `scripts/run_partition_study.py` and `results/partition_study.md`, which sweep dataset size and show `by_date_symbol` getting *worse* as data grows while `sorted` (large files, symbol-clustered, statistics on) stays fast.
